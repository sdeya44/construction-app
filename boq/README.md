# KAYAN BOQ — כתבי כמויות, הצעות מחיר וחשבונות

תוכנה לניהול כתבי כמויות, הצעות מחיר מבוססות דקל, חשבונות חלקיים וסופיים, קבלני משנה ותשלומים.
פועלת כתוכנת Windows (קובץ התקנה) וגם בדפדפן. משתמש יחיד, נתונים מקומיים בלבד.

## התקנה ב-Windows
1. GitHub → Actions → **KAYAN BOQ — Windows build** → הריצה האחרונה → Artifacts → `KAYAN-BOQ-Setup`.
2. חלץ והרץ את `KAYAN BOQ Setup.exe`. (הקובץ אינו חתום דיגיטלית — Windows SmartScreen יבקש "More info → Run anyway").
3. בפתיחה הראשונה: **הגדרות → טעינת מחירון** ובחר את `dekel_pricelist.db`.

הנתונים נשמרים ב-`%APPDATA%\KAYAN BOQ\data\kayan.db`. כל שמירה אטומית (קובץ זמני → החלפה),
ונשמרים עד 20 גיבויים אוטומטיים בתיקיית `backups` (אחד לכל 10 דקות עבודה ובכל הפעלה).
גיבוי ידני לקובץ ושחזור — במסך ההגדרות. תפריט קובץ → "פתיחת תיקיית הנתונים".

## עבודה בדפדפן
פתח את `index.html` דרך שרת (למשל GitHub Pages: `/boq/`). הנתונים נשמרים בדפדפן (IndexedDB) —
ניקוי נתוני גלישה ימחק אותם, לכן יש לגבות לקובץ. הורדת מדדים אוטומטית זמינה רק בגרסת Windows.

## מחירון דקל
המחירון הוא מידע מורשה ולכן **אינו חלק מהתוכנה ואינו נשמר בריפו** (הריפו ציבורי). נטען פעם אחת מקובץ
ונשמר במחשב בלבד. בשנה חדשה — טוענים קובץ חדש; סעיפים מקושרים שומרים את מחיר הייחוס, ומסך
"בדיקת תמחור מול דקל" מציג פערים ומאפשר עדכון.

- **חיפוש ושליפה**: פאנל דקל בכתב הכמויות — חיפוש חופשי/קוד, סינון פרק, הצעות התאמה לסעיף הנבחר.
  התוכנה לעולם לא בוחרת סעיף דקל לבד: סעיפים רבים נבדלים רק בטווח כמות/עומק.
- **בדיקת תמחור**: סטייה % לכל סעיף מקושר, מול סף שנקבע לכל פרויקט (ברירת מחדל 15%), ייצוא CSV.
- **הצעת מחיר**: מחיר = דקל × (1 + % כללי) × (1 + % לפרק). עריכת מחיר בסעיף הופכת אותו לידני.
  "המרה לחוזה" יוצרת חוזה מזמין מההצעה.

## SKN (משהב"ש / בנארית)
ייבוא וייצוא לפי המבנה שאומת מול ייצוא אמיתי של בנארית: רשומה = 2 שורות × 183 תווים, CRLF, cp1255.
בייבוא מזוהים גם cp862 ו-UTF-8. הייצוא נכשל במפורש (לא מעגל בשקט) על כמות/מחיר שליליים, חריגה ממגבלות
הרוחב ויחידה ללא קוד SKN, ומדווח על כל עיגול ל-2 ספרות ועל המרת יחידות (מטר → מ"א).

## חשבונות — כללי החישוב
1. שורה = כמות × מחיר × אחוז תשלום / 100, מעוגל לאגורה פעם אחת. כל החישוב בשלמים (ללא נקודה צפה).
2. הנחת פרק → הנחה כללית על פרקים שאינם מוחרגים (פרק 99 מוחרג כברירת מחדל).
3. מצטבר: ביצוע לתקופה = מצטבר נטו − מצטבר נטו מאושר קודם. סעיף שלא עודכן שומר את המצטבר הקודם.
   תקופתי: כל תקופה במחיריה, המצטבר מסכם היסטוריה.
4. סיווג: לפי כמות חוזה / מעל כמות חוזה / נוספות (סעיפים חריגים או פרק 99).
5. + התייקרות (מלאה / מעל סף / חלקית / ידנית; מדד בסיס וחודש קובע לכל חוזה) − עיכבון + שחרור עיכבון
   − קיזוז מקדמה (אוטומטי לפי % עד גובה המקדמה, או ידני) − קיזוז חומרים − הפחתות אחרות = לפני מע"מ; + מע"מ.
6. אישור שומר תמונת מצב קפואה (כולל ערכי המדד). חשבון מאושר אינו ניתן לעריכה; אישור לפי הסדר;
   חשבון אחד פתוח בכל רגע; חשבון סופי מאושר סוגר את החוזה. אישור נחסם כשחסר ערך מדד.

נבדק מול חשבון 8 (חנתון): 5,244,370.40 → הנחה 0.5% → +219,098 ללא הנחה → −4,737,554.43 → מע"מ 18% → 825,636.70.

## שלב 2 — מה נוסף
- **Excel:** ייצוא כתב כמויות וחשבון (עם נוסחאות חיות) וייבוא עם מיפוי עמודות; קובץ שיוצא מהתוכנה חוזר אליה זהה.
- **ייבוא PDF:** קורא כתבי כמויות וחשבונות בפורמט בנארית (קוד, תיאור, יחידה, כמות, מחיר) ומציג מסך בדיקה לפני שמירה.
  נבדק על חשבונות 6 ו-7 של חנתון: 257/257 סעיפים עם כמות, מחיר ויחידה נכונים; תיאורים ~90% זהים (ריווח בתוך ה-PDF).
- **פתיחה מחדש של חשבון מאושר:** רק האחרון, ללא תשלומים, עם סיבה ביומן.
- **קבלת תשלום מרוכז:** תשלום אחד מתחלק בין חשבונות (מהישן לחדש או ידני), סכום ההקצאות חייב להתאים.
- **קיזוז רכש:** הזמנה/תעודת משלוח/חשבונית; קישור בין מסמכים מונע קיזוז כפול; ננעל עם אישור החשבון.
- **מצב חוזים לתאריך:** חיתוך לפי תאריך אישור ותאריך תשלום.
- **רווח מול קבלני משנה:** מתוכנן ובפועל לכל סעיף, מסעיפים שהועתקו מחוזה המזמין.
- **ליקויים:** רישום לכל פרויקט, שיוך לחוזה/קבלן, חומרה, אחראי, יעד וסטטוס.

## שלב 3 — מה נוסף
- **מכרזים והשוואת הצעות:** מכרז על כל כתב הכמויות או על פרק; מציעים עם הנחה כללית; טופס Excel לכל מציע
  (עמודת מחיר בלבד פתוחה לעריכה) וקליטתו חזרה לפי מספר סעיף; השוואה לכל סעיף מול אומדן ודקל, הזול מסומן,
  סטייה של ±15% מהאומדן מסומנת; בחירת זוכה יוצרת חוזה קבלן משנה מקושר לסעיפי המקור.
- **תזרים מזומנים:** תקבולים ממזמינים מול תשלומים לקבלני משנה לפי חודש — בפועל (תשלומים שנרשמו),
  צפוי (יתרות חשבונות מאושרים לפי שוטף+ימים) ותחזית (יתרת ההיקף מחולקת עד חודש הסיום). חוזה ללא חודש סיום מוצג באזהרה.
- **דוחות מנהלים:** לכל פרויקט — היקף, ביצוע, יתרה לגבייה ולתשלום, רווח מתוכנן ועל הביצוע, חריגות כמות,
  עבודות נוספות, חריגות מדקל וליקויים פתוחים/באיחור.
- רווח "על הביצוע" = כמות שאושרה אצל המזמין × (מחיר מזמין − מחיר קבלן), כך שעיכוב בחשבון הקבלן לא מנפח את הרווח.

## דפי חישוב כמויות
הוטמע מנוע חישוב הכמויות מגרסת KAYAN execution-accounts (v3.0.0, ענף `claude/kayan-execution-accounts-gyx9hw`) — הקוד הועבר כפי שהוא:
- **יחידה קובעת סוג מדידה:** מ"ר → שטח, מ"ק → נפח (חתך × עובי/אורך), מטר/מ"א → אורך, שאר היחידות → ספירה.
- **צורות:** מלבן, משולש, טרפז, עיגול, חצי עיגול, שטח מיוחד; מכפיל N; ± הפחתה (פתחים); קבוצות; קיבוץ לפי אזור.
- **שרטוט ונוסחה חיים:** לכל שורה שרטוט SVG (איזומטרי לנפח) ונוסחה עם המספרים שהוזנו, למשל `(5 × 2) × 0.3 × 4 = 12`.
- **נתבע מול מאושר:** החלטת מפקח לכל שורה (מאושר כמוגש / הפחתה / דחייה / ממתין); שינוי מידות אחרי החלטה מחזיר אותה ל"ממתין".
- **קישור לחשבון:** סעיף עם דף חישוב מקבל את הכמויות אוטומטית — סה"כ נתבע לכמות מחושבת ומוגשת, סה"כ מאושר לכמות מאושרת.
- **היסטוריה:** אישור חשבון מקפיא את השורות ורושם היסטוריה לכל שורה (נוצר/תוקן/בוטל); שורה שאושרה לא נמחקת אלא מבוטלת.
- **הדפסה:** מצטבר / רק תנועה בחשבון; תמציתי / מפורט; לרוחב / לאורך; סעיפים להצגה (הכל / עם כמות / עם שינוי / עם דף חישוב);
  כל סעיף בדף נפרד, כרטיסי סיכום, חוזי מול מדידה; דף חישוב לסעיף בודד עם היסטוריית ביקורת; חתימות קבלן/מפקח/מנהל פרויקט.

## זרימת עבודה — הצעה ← חוזה ← חשבונות
- **דף הפרויקט** מציג את הרצף: הצעות מחיר וגרסאות ← חוזה (כמויות מכרז) ← חשבונות, עם מצב כל שלב ויתרה לגבייה.
- **גרסאות:** "כלים ← גרסה חדשה" — עותק מלא או לפי פרקים נבחרים (למשל בטונים בלבד), עם תווית גרסה.
  "העתקה לפרויקט אחר" ו"ייבוא ← העתקת פרקים מכתב כמויות אחר" עובדים בין פרויקטים. "השוואת גרסאות" — סעיף-סעיף ולפי פרקים.
- **מהדורות הצעה:** "הפקת מהדורה" שומרת עותק קפוא של מה שנשלח (נמען, תאריך, סכום) ומדפיסה אותו. ההצעה ממשיכה להשתנות,
  ותמיד אפשר להשוות אותה למהדורה שנשלחה.
- **נעילת כתב הכמויות החוזי:** "אישור והמרה לחוזה" נועל מיד; חוזה שנפתח ידנית ננעל בחשבון הראשון. כמות, מחיר, יחידה,
  מספור והנחות פרקים קפואים. סעיף חדש נשמר כחריג "ממתין לאישור" ונעשה חלק מהחוזה רק לאחר אישור. ביטול נעילה — רק לפני
  החשבון הראשון, עם סיבה ביומן.
- **מקור כמות לכל סעיף:** הקלדה בחשבון או דף חישוב (נבחר בדף החישוב). פתיחת דף חישוב לסעיף שכבר חויב ידנית שומרת את
  המצטבר כ"יתרת פתיחה" — המצטבר לא יורד. כמות נוכחית שלילית מוצגת כהתראה ודורשת אישור לפני הגשה.
- **שורת מדידה שאושרה נעולה:** מידות, החלטת מפקח ומחיקה חסומים. "✎ תיקון שורה" (עם סיבה) מבטל את המקור — שנשאר
  בהיסטוריה — ויוצר שורה זהה לעריכה; בחשבון הבא ההפרש מופיע כתיקון גלוי.
- **סטטוס חשבון:** בהכנה ← הוגש ← הוחזר לתיקונים ← הוגש מחדש ← מאושר. מצב גבייה נגזר מהתשלומים: ממתין לתשלום /
  שולם חלקית / שולם. "מהלך החשבון" (בלשונית תשלומים) רושם כל מעבר עם תאריך והערה.
- **לתשלום מול לגבייה:** החשבון מנכה את מה ש**אושר** בחשבונות קודמים (לא את מה ששולם — אחרת נתבע שוב סכום שכבר אושר).
  בסיכום מופיעים גם "יתרת חוב מחשבונות קודמים" ו"סה"כ לגבייה".

## נוחות שימוש
- **מסך בית — "דורש טיפול":** חשבונות בהכנה / הוחזרו לתיקונים / הוגשו (עם מספר ימים) / ממתינים לתשלום, מדדים חסרים,
  שורות מדידה ממתינות וסעיפים חריגים לאישור — כל כרטיס פותח את המקום לטיפול.
- **אשף המרה לחוזה** בשלוש לשוניות: פרטים ← תנאי תשלום ← הצמדה. שם החוזה מוצע "חוזה — …", המזמין ממולא מהפרויקט.
  גם הגדרות החוזה מחולקות ללשוניות.
- **חשבון:** החודש הבא מוצע אוטומטית; אחרי אישור — "+ פתיחת חשבון N"; 📐 בכל שורה פותח דף חישוב לסעיף.
  בהגשה הכמות שהוגשה הופכת לנקודת המוצא של המאושר, והחשבון מחושב לפי המאושר — אין צורך לבחור "בסיס".
  במצב "הוגש" מוצגות זו לצד זו: מצטבר מאושר (לעריכה) ומצטבר שהוגש. "גרסאות כמות" נשאר כאפשרות מתקדמת.
- **פתיחה מחדש:** כשאינה אפשרית מוסבר מראש למה (חשבון מאוחר יותר / תשלומים) ומה לעשות.
- **כתב כמויות:** יחידה מרשימת יחידות בנארית; כפתור "הגדרות פרק" גלוי כשנבחר פרק; תיאורים והערות מקופלים לשתי שורות
  עד לעריכה; פאנל דקל נפתח אוטומטית רק בהצעות מחיר.

- **הוספת סעיף בתוך הטבלה:** השורה האחרונה בכתב הכמויות — תיאור ← יחידה ← כמות ← מחיר, Enter שומר ומחזיר לשורה חדשה.
  המספור נקבע אוטומטית בתת-הפרק הנבחר.
- **ביטול / חזרה (↶ ↷, Ctrl+Z / Ctrl+Y):** מבטל את השינוי השמור האחרון (עד 30 צעדים), כולל אישור חשבון או ייבוא.
- **חיפוש דקל מדורג:** קוד מדויק, הביטוי כפי שהוקלד ותחילת התיאור קודמים; "פירוק", "תיקון", "חומר בלבד" ו"תוספת" יורדים
  למטה אם לא חיפשו אותם; התאמה גם בצורות שונות של המילה (קיר/קירות, אבן/אבנים).
- **עזרה:** זרימת העבודה, מילון מונחים וקיצורי מקלדת (בתפריט העליון).
- **דף החישוב** במסך מקבל את עיצוב התוכנה (ואת מצב התצוגה שנבחר); התדפיס נשאר זהה למקור.
- **מסך צר (מחשב נייד):** הפס העליון מתכווץ ועמודת "% ביצוע" מוסתרת — בלי גלילה הצידה.
- **ביצועים:** נבדק על כתב כמויות של 3,000 סעיפים ו-6 חשבונות: עריכת כמות בחשבון ~0.2 שנ׳ (עדכון התאים במקום, בלי
  ציור מחדש), פתיחת חשבון ~1.2 שנ׳, כתב כמויות ~0.8 שנ׳.

## פיתוח
```bash
npm install      # Electron + electron-builder
npm test         # 55 בדיקות: מנוע, SKN, API, Excel, PDF, שלבים 2–3, דפי חישוב, זרימת עבודה
npm start        # הפעלת גרסת Windows מקומית
npm run dist     # בניית קובץ התקנה (ב-Windows / ב-CI)
```
מבנה: `js/money.js` חשבון עשרוני מדויק · `js/engine.js` מנוע חשבונות · `js/skn.js` · `js/dekel.js` ·
`js/api.js` כללי עסק וטרנזקציות · `js/ui/*` מסכים · `electron/*` מעטפת Windows.
