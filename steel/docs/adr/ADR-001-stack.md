# ADR-001 — Stack טכנולוגי

**סטטוס:** מאושר · **תאריך:** 14.11.2026

## החלטה
אפליקציית דפדפן (PWA) ב-**TypeScript** עם **three.js** לתצוגה תלת־ממדית, **React** לממשק בלבד, **Vite** לבנייה, **Vitest** לבדיקות יחידה ו-**Playwright** לבדיקות דפדפן אמיתיות. שמירה מקומית ב-**IndexedDB**, גיבוי/שחזור כקובץ JSON עם גרסת סכמה.

## נימוק
| דרישה | איך ה-Stack עונה |
|---|---|
| Windows בדפדפן + טלפון, ללא התקנה | PWA רץ ב-Edge/Chrome, ניתן להתקנה, עובד Offline |
| דיוק גיאומטרי | גיאומטריה מחושבת בשכבה טהורה (`src/geometry`) ב-double, ב-mm; three.js מקבל משולשים מוכנים בלבד |
| 10,000 אלמנטים | כל האלמנטים ממוזגים לגיאומטריה אחת (קריאת ציור אחת), מיפוי משולש→אלמנט לבחירה |
| מקור אמת אחד | `Project` (פרמטרים + התאמות) → `generate()` דטרמיניסטי → כל המבטים, הכמויות, ובהמשך השרטוטים |
| רישוי מסחרי | three.js, React, Vite — MIT. אין תלות ברישיון GPL/מסחרי |

## חלופות שנפסלו
- **Babylon.js** — טוב, אך three.js בשל יותר לכלי CAD-ווב ויש לו CSS/raycast גמישים יותר; אין יתרון מהותי.
- **OpenCascade.js (B-Rep)** — מנוע CAD אמיתי, אך WASM כבד (~30MB), איטי לטעינה בטלפון. אקסטרוזיה + חיתוכים מישוריים מספיקים לפרופילים ישרים בשלב 1. **ייבחן מחדש** ל-IFC/STEP ולחיתוכים מורכבים (Coping).
- **Electron / אפליקציה שולחנית** — מוסיף התקנה ועדכונים; לא נדרש. אפשר לעטוף בעתיד.
- **React-Three-Fiber** — נוח, אך שליטה אימפרטיבית (מצלמות, בחירה, Scissor למספר מבטים) פשוטה יותר ב-three ישיר.

## השלכות
- גיאומטריה מורכבת (חיתוכי Coping, ריתוכים) תדרוש בשלב M3 הרחבה של `solid.ts` או מנוע B-Rep.
- הפקת PDF/DXF (M4) תתבצע מהמודל ולא מצילום מסך: ספריות jsPDF/כותב DXF עצמאי — לבדיקת רישוי בשלב M4.
