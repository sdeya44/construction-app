# KAYAN STEEL PRO — פרומפט הקשר לפרויקט (מצב: גרסה 1.73.0; ענף claude/brave-wozniak-4wyvus)

אתה עובד על **KAYAN STEEL PRO** — תוכנה לתכנון, מידול וייצור של סככות ומבני פלדה (מסגרות פורטל), של כיאן הנדסה.
ענה תמיד בעברית. כל טקסט בממשק — בעברית, מימין לשמאל. מונחים טכניים, קוד, פקודות ושמות קבצים — כמו שהם.

---

## 1. מה התוכנה עושה

תוכנת דפדפן (קובץ HTML יחיד, עובד גם בלי שרת) שבונה מודל תלת-ממדי פרמטרי של מבנה פלדה, ומפיקה ממנו שרטוטי ייצור, רשימות וקבצי מכונה.

**מבנה ראשי**
- מסגרות פורטל: צירי עמודים, מסגרות לאורך המבנה, גבהים ושיפועים. דו-שיפועי, חד-שיפועי, רב-מפתחי, ותבניות חתך מודולריות: מדורג, פרפר, שן מסור, מוניטור, אסם, סככה צמודה, קונזולה ועוד.
- מפלס בסיס ותחתית עמוד לכל ציר.
- חתכים וחומרים: קטלוג פרופילים, אימות מקטלוג, ייבוא קטלוג מאקסל, והצעת חתכים אוטומטית (sizing).

**רכיבים**
- **פטות:** C/Z לכל שיפוע. כוללות תושבות (זוויתן שוכב / זוויתן עומד / פלטה + משולש / פרט מותאם), חיבורי המשך, ופריסה אוטומטית או ידנית.
- **חיזוקים:**
  - אלכסוני עמוד-קורה, עם 6 מידות ששתיים מהן קובעות;
  - מכפל בראש העמוד;
  - קושרות גג: X מזוויתנים או סבכה אופקית RHS, ותמוכות בין הקורות;
  - קשיחות קירות: X, אגד B או מסבך נעילה, וסיב רציף;
  - שורות קשירה לפטות, מוטות תלייה, תמיכה צידית;
  - חיזוק רכס.
- **חיפוי:** חיפוי גג וקירות, פטות קיר, עמודי רוח, פתחים, מזחלות ומרזבים, וכתב כמויות חיפוי.
- **רכיבים מיוחדים:** דילול עמודים עם קורה או מסבך נושא (כולל אלכסוני Y), כנף L, ומסבכי גג.

**חיבורים**
- מנוע חיבורים פרמטרי לכל סוג: ראש עמוד, רכס, פלטת בסיס עם ברגי עיגון, תושבת פטה, המשך פטה, המשך קורה, קצה קושרת, הצטלבות, אלכסון ועוד.
- אשף מחברים (החלפת פרט), סטודיו פרטים לבניית פרט מותאם מחלקים, וספריית פרטים של הפרויקט עם פרטים מוכנים.

**בדיקות ותקינות**
- רשימת שגיאות ואזהרות (התנגשויות, גיאומטריה, פרטים) ותיקון אוטומטי.
- **אין בדיקת חוזק מלאה.** יש ניצולת רק לקורות הנושאות. המודל מסומן "אינו תכן מאושר".

**שרטוטים (PDF / DXF / SVG)**
- גיליון שער, שרטוט כללי, תוכנית הרכבה, סדר הקמה ומשקלי הרמה.
- תוכנית גג, תוכנית ברגי עיגון, חתכי מסגרות, חזיתות, קירות קצה, חיפוי ומזחלה.
- פרטי חיבור, שרטוטי מכלול וחלק, גיליונות פלטות, ותוויות סימון.
- סטטוס ומהדורות.

**ייצור והפקה**
- מספור חלקים ומכלולים, כתב כמויות, קבצי מכונה DSTV, IFC.
- ייצוא וייבוא קובץ פרויקט, והצעת מחיר.

**ניהול**
- שמירה אוטומטית בדפדפן (IndexedDB) עם גרסאות ושחזור, Undo/Redo מלא, ונעילת מהדורה מאושרת.
- חיפוש Ctrl+K, וגיליון פרמטרים (כל המידות בטבלה).

## 2. ארכיטקטורה

- **טכנולוגיה:** React 18 + TypeScript + Vite + three.js. הקוד בתיקייה `steel/` בריפו `sdeya44/construction-app`.
- **זרימת נתונים:** `store.exec(Command)` ← `History`, היסטוריה של מצבים לא משתנים (immutable) ← `generate(project)` ← `DerivedModel` (אלמנטים, חיבורים, בדיקות). הממשק מציג את `DerivedModel`, ולכן מה שרואים הוא מה שנבנה.
- **טרנזקציית אשף:** `History.txBegin / txCommit / txCancel`. כל מה שנעשה באשף מוצג מיד במודל, ו"אישור" שומר אותו כצעד Undo אחד.
- **קבצים מרכזיים:**
  - `src/geometry/*`: המנוע.
  - `src/drawing/*`: השרטוטים.
  - `src/fab/*`: ייצור, כתב כמויות, DSTV ו-IFC.
  - `src/ui/*`: הממשק.
  - `src/view/*`: התצוגה התלת-ממדית, ו-`realView.ts` לתמונות הריאליסטיות.
- **אסור לשנות** את מנוע המידול, החישובים, מודל הנתונים או יצירת שרטוטי הייצור, אלא אם התבקש במפורש.

## 3. הממשק היום (1.64)

- **פס עליון כהה:** שם הפרויקט, שמירה, ביטול ושחזור, חיפוש, קובץ (חדש / פתיחה / ייצוא). אין ריבון; הוא הוסר ב-1.61 כי היה כפול לאשפים.
- **המודל התלת-ממדי** תופס את רוב המסך. סרגל צף עם מבטים, מידות ושכבות, וסרגל כלים תחתון (בחירה, מדידה, גדלים, חתך ועוד).
- **סרגל שלבי העבודה בצד ימין** (`StepsRail`):
  - 13 שלבי הגדרה + 3 שלבי הפקה. אפשר לכווץ לנקודות.
  - ארבעה מצבים: הושלם (ירוק) / לא הוגדר / לא נדרש / הערות (כתום). המצבים נשמרים ב-`meta.steps`.
  - "הושלם" רק אחרי "אישור" באשף.
  - לחיצה על רכיב שלא קיים פותחת שאלה: הוספה / לא נדרש / ביטול.
  - קבוצת **"כלים"**: רשימות (אלמנטים / חיבורים / בדיקות), גיליון פרמטרים, ספריית פרטים, כתב כמויות חיפוי.
- **פרויקט חדש:** רכיבים אופציונליים כבויים (קושרות, קשיחות קירות, שורות קשירה, חיזוק רכס).

**מערכת האשפים האחידה** (`ComponentWindow` + `src/ui/wizard/*`). כל רכיב נפתח בחלון צף אחד, באותו מבנה:
1. **סוג:** אריחים עם תמונה ריאליסטית קבועה, ו"פעיל".
2. **"השינויים יחולו על":** האלמנט שנבחר / ציר / שיפוע / כל המודל. ההיקף מודגש בכתום במודל, ויש העתקה והדבקה של הגדרות.
3. **שלוש קבוצות:**
   - **1 מיקום במבנה**
   - **2 גיאומטריה**
   - **3 חתך ומחברים:** חתך למעלה, ואחריו **בלוק מחבר אחד** (`ConnectorBlock`):
     - לשוניות מחברים;
     - פרט החיבור: "פרט מובנה" או "מהספרייה / פרט מוכן";
     - סטודיו.
4. **תקינות** בתוך האשף.
5. **פעולות:** שחזור / ביטול / אישור. במצב הוספה הכפתורים הם "הוספה למבנה" / "ביטול ההוספה".

**האשפים הקיימים**
- `WallsStudio`: קשיחות קירות.
- `KneeStudio`: אלכסון עמוד-קורה או מכפל.
- `FamilyStudio`, אשף כללי לפי טבלה `FAMILIES`: קושרות גג, פטות (קשירה / מוטות / תמיכה), חיזוק רכס, פטות ותושבות, קירות וחיפוי, דילול עמודים, כנף, מסבכי גג, מסגרות.
- `ElementStudio`: אלמנט בודד (עמוד, קורה, פטה, פלטה). כרטיס האלמנט, מחולק לקבוצות דרך `CardPartCtx`.

**חתך המסגרת** (`FrameSection`, בגיאומטריה של "צירים ומסגרות")
- שרטוט אחד עם כל המידות:
  - בכל ציר: ראש עמוד (לפי מישור החיתוך בפועל) וע.ע. קורה (לעריכה);
  - רכס, שיפועים, מפתחים, קונזולות;
  - תחתית עמוד ומפלס בסיס.
- פעולות על השרטוט: "+ ציר", מספר צירים / רוחב (חלוקה שווה), ובועת ציר (שם, קיר קיים, מחיקה).
- בחירה "רק בציר הזה" / "כל הגג", וייחוס פני קורה / ציר קורה.

**מידות נעולות:** אלכסון עמוד-קורה (פותר על המודל, `kneeSolve`) ואגד B (`LockedDims`, משולש אנליטי).

**אין תלת-ממד חי בתוך האשפים.** הוא הוסר לבקשת המשתמש כי הכביד. המודל הראשי הוא התצוגה.

**מסך צר / טלפון:** עדיין עץ התפריטים והפאנלים הישנים.

## 6. מה נשאר (לפי עדיפות)

1. **שרטוטים** (דירוג המשתמש: 60%):
   - סידור גיליון וטבלת כותרת אחידה;
   - מידות מלאות בחתך המסגרת;
   - בפרטי חיבור: חתך דרך הפלטה, סמלי ריתוך לפי ISO 2553, כיתוב ברגים, מרחקי קצה;
   - במכלול ובחלק: מידות מנקודת אפס וטבלת חורים;
   - קריאות בהדפסה.

   ממתינים לשרטוטי ייחוס מהמשתמש.
2. **חוויית שימוש:**
   - עורך החיבור ובחירה מרובה במבנה האחיד;
   - קיצורי מקלדת (Enter / Esc / 1-2-3) וזיכרון הקבוצה האחרונה;
   - הרחבת המידות הנעולות;
   - אשף שעובד בטלפון, ואז מחיקת הקוד הישן (פאנלים, עץ, ריבון).
3. **קבצי ייצור:** אימות DSTV ו-IFC מול מכונה ותוכנה אמיתיות.
4. **בדיקות חוזק** לפי תקן (ת"י 1225 / יורוקוד 3), ככלי עזר. ממתין להחלטת המשתמש.
5. **הרצה מלאה** של כל הבדיקות לפני שימוש בשטח (רק כשהמשתמש מבקש).

- **1.66** פלטת רכס בעובי אמיתי; מסבך גג בכל מפתח במסגרת רב-מפתחית (`.S<n>`); אלכסוני מסבך ברכס בלי חדירה; מהירות זום 3× (תפריט שכבות).
- **1.67** ספריית מחברים: 7 מחברים מוכנים (`src/geometry/data/connLibrary.json`) עם תנאי התאמה (`presetFits`), ייבוא/ייצוא (`detailLibrary.ts`); תיקוני מתכונים (תושבת מושב, תושבת פטה כפולה).
- **1.68** ביקורת קריאות גיליונות (`drawing/layoutAudit.ts`) והצבת תוויות (`drawing/labels.ts`); 309 חפיפות → 1 בפרויקט מלא; `tests/layout.test.ts` עם תקרות לצורות נוספות.
- **1.69** גיליון מכלול אגד B / אלכסוני Y (`drawing/unit.ts`): מבט, פרטים מוגדלים עם סמלי ריתוך, פרטי פלטות, טבלה; **1.69.1** + תלת־ממד. הפניית חורים "n × Ød"; פלטה גדולה/מסובכת בגיליון משלה; תיאור פלטה לפי הגיאומטריה בפועל.
- **החלטות משתמש:** סגנון השרטוטים שלנו נשאר; כמה פלטות בגיליון, **בלי** טבלת קדחים; **בלי** טבלאות ברגים/ריתוכים בגיליון חיבור; לא לקחת את מבנה המכלול/חלק של חבילת 1.70.

## 8. חבילת KAYAN 1.70 (קובץ חיצוני — לא בריפו)
המשתמש העלה `KAYAN-ESSENTIAL-CODE.zip` (SHA-256 `ce82a0e3…`). הבסיס שלה = התוכנה שלנו בגרסה 1.65 בנויה + שכבת מודולים. **מה כבר נלקח:** רעיון ביקורת ה-CAD, 7 המחברים, רעיונות layout-audit/placeLabels, 3 התיקונים (רכס, מסבך, זום).
**הקבצים הדרושים לשלבים הבאים הועתקו ל-`vendor/kayan170/` (ראו README שם) — אין צורך להעלות את ה-zip מחדש.** מה נשאר ממנה: `polygon-nesting.mjs` (קינון פלטות), עובי מסור/קיטום מ-`bar-planning.mjs`, `revision-diff.mjs` (השוואת מהדורות), לחצן "שרטוט מדויק" — קווים נסתרים וחתכים במנוע OCC שנטען מהאינטרנט לפי דרישה (החלטת משתמש: לא להטמיע בקובץ), STEP למכלול/בחירה.
**לא לקחת:** Electron/מתקין, קורא NC1 ב-.NET, production.mjs.

## 9. מה הלאה (לפי עדיפות)
1. **מערכת מחברים מאוחדת** — `docs/connector-system-plan.md` (שלבים A–G). **A+B בוצעו ב-1.71.0** (`docs/connector-mapping.md`: מיפוי ופערים G1–G14; מתכון v2: `params` + `detailParams` + אשף דינמי). **שלב C בוצע (1.72.0):** המתכון `kneeFinRecipe` שקול לקוד הישן (CONV-01/02, CAD-04) ונחשף כדגל `kneeBraces.finEngine: 'recipe'` (כבוי כברירת מחדל; הקוד הישן נשאר — `docs/connector-mapping.md` סעיף 6.1). נסגרו חובות לפני D: אשף מחיבור `custom` (`familyOf`/`underlyingConn`), ביצועי `applyCustomDetails` (`rayGeom`, ראו 6.2). **שלב D בעיצומו (1.73.0):** strut `fin` הוסב ונבדק (STRUT-01..03, CAD-05), הדגל `rafterStruts.finEngine` ללא ממשק — מחכה לאישור חריגים (`connector-mapping.md` 7.1). **הבא:** strut `endplate` (אתר זוגי, G8) ו-`weld`. (המשך המסמך — מטרת C המקורית:) — פיילוט הסבה: אלכסון עמוד-קורה פח+לשונית עם קיטום פינות ובורג אחד, עם השוואה אוטומטית מלאה מול הקוד הישן (תנאי מעבר מפורטים בסעיף 4 של `connector-mapping.md`). לפני C: לפתור שפתיחת אשף חיבורים מחיבור `custom` לא נתמכת, ומטמון לפי חתימת אתר+פרמטרים.
2. **כלי אופטימיזציה — צמצום סוגים** (`docs/rationalization-plan.md`): פלטות, דפוסי חורים, אורכי אלכסונים.
3. "שרטוט מדויק" (OCC לפי דרישה) + STEP למכלול.
4. קינון פלטות + עובי מסור/קיטום בתכנון מוטות; השוואת מהדורות.
5. ניקוי גיליונות צפופים (קירות קצה, מכלולי מסבך, תוכנית גג) — תקרות ב-`tests/layout.test.ts`.
6. פתוח: חריץ ה-RHS לשונית לא מופיע ב-NC1 (DSTV); אישור `WELD_GAP_MAX`; הרצה מלאה לא בוצעה מאז 1.64.
